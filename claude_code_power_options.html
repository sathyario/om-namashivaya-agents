/advisor Smartest
Sonnet executes, Opus advises — best quality at lower cost
Enable this first for any complex build. Opus only kicks in for hard architectural decisions. 74.8% on SWE-bench with 11.9% lower cost vs Sonnet alone.
/batch Parallel
Run changes across multiple files in parallel worktrees
Decomposes work into 5–30 independent units, each running in its own git worktree. Perfect for migrations, refactors, adding tests across all files.
/batch add input validation to every FastAPI endpoint in src/routes/
/simplify 3 agents
3-agent parallel code review — run after every feature
Spawns 3 parallel agents reviewing from different angles. Catches unused imports, redundant logic, complexity issues. Run after every AI-generated code block.
/security-review Pre-deploy
Scans current git branch diff for vulnerabilities
Run before every PR merge. Scoped to your branch changes only — not the whole codebase. Essential before deploying auth, payments, or APIs.
/compact Token mgmt
Compress context when it hits 80% — never lose progress
When context fills up, this compresses history into a dense summary. You can guide what it keeps.
/compact Focus on auth module and current test failures

CLI flags — launch-time power options
Shift+Tab Most used
Cycle: Normal → Auto-accept → Plan mode
Plan mode = Claude reads everything but makes zero changes. Use before touching production-critical code, DB migrations, or auth flows.
claude -c Resume
Continue last session — pick up exactly where you left off
Don't re-explain your project every time. Resume with cached context and all prior decisions intact.
claude -p "prompt" CI/CD
Non-interactive mode — scriptable for CI pipelines
Run Claude Code in GitHub Actions, cron jobs, or shell scripts. One-shot query that exits after completion.
claude -p "Fix all TypeScript errors" --output-format json
--append-system-prompt Custom persona
Add instructions to Claude without replacing defaults
Make Claude act as a senior backend engineer, security auditor, etc — while keeping all its built-in capabilities.
claude --append-system-prompt "You are a senior FastAPI engineer. Always write async endpoints and include error handling."
--worktree / -w Safe edits
Isolated git worktree — changes never touch main branch
Perfect for risky refactors or experiments. Auto-cleaned if no changes made. You review before merging.
permissions in settings.json Security
Control exactly what Claude can read/write/run
Never let Claude touch .env files, production configs, or run sudo. Lock it down for team use.
{ "permissions": { "allowedTools": ["Read", "Write(src/**)", "Bash(git *)"], "deny": ["Read(.env*)", "Write(production.config.*)", "Bash(rm *)"] } }
Hooks — automatic actions on Claude's events
PostToolUse hook Auto-format
Run formatter/linter automatically after every file edit
Claude writes code → your linter runs automatically → no manual formatting ever. Production code stays clean without effort.
{ "hooks": { "PostToolUse": [{ "matcher": "Write(*.py)", "hooks": [{ "type": "command", "command": "python -m black $file" }] }] } }
PreToolUse hook Type check
Run type check BEFORE accepting changes
Catch TypeScript/mypy errors before they land in your codebase. Claude's change gets blocked if types fail.
/hooks View all
See all configured lifecycle hooks in your session
Audit what's running automatically in your session at any time.
Pro tip: Hooks + /batch = Claude makes changes across 20 files AND auto-formats + type-checks all of them. Zero manual work.
The production workflow — use this sequence every day
Step 1Setup once
Create CLAUDE.md, .claudeignore, permissions in settings.json, hooks for auto-format.
touch CLAUDE.md .claudeignore claude # first launch, set up /advisor with Opus
Step 2Every feature
Plan → build → review → clear context. Never let context overflow.
Shift+Tab # switch to Plan mode first # describe the feature, review Claude's plan Shift+Tab # back to normal mode # Claude builds it /simplify # 3-agent review /security-review # check for vulns /compact # compress before next feature
Step 3Big refactors
Use /batch for cross-file changes. Use -w worktree flag for risky work.
claude -w # isolated worktree /batch add error handling to all route files in src/
Step 4CI/CD integration
Run Claude non-interactively in GitHub Actions for automated reviews.
claude -p "Review this PR diff for security issues" \ --output-format json > review.json
Monthly: run /insights to see your usage patterns, costs, and where Claude is spending most tokens. Optimize from there.
